The problem
A browser and desktop multiplayer RPG needs an economy and combat system a modified game client can't edit — the standard exploit path in online games.
What I did
Built a Flask + SQLite backend that owns every XP gain, loot roll, and gold amount, and validates each hit against what a character should actually be able to deal.
Tools I used
Godot, GDScript, Flask, SQLite, WebSockets
My decision
One player's game simulates the shared monsters, for performance, but the server stays the only source of truth for their health and kill payouts — a modified leader can move monsters around but can't pay itself, or anyone else, an illegitimate kill.
What was hard
A peer security review flagged a missing token-lifecycle defense. The fix meant binding every login to a random per-install id, so a stolen session token used from a different copy of the game is caught and signed out instead of just trusted.
The result
Shipped and live with real players. A 128-player stress test showed the server handling it at 11% of one CPU core — data volume, not processor power, turned out to be the actual scaling limit.
